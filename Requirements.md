# Техническое задание
## Приложение судейского хронометража и учета результатов

## 1. Назначение
Приложение предназначено для судей на соревнованиях и помогает фиксировать старт, финиш, ручное время судьи, штрафы и итоговый результат участника. Приложение должно работать локально на Windows 10/11, запускаться как exe-файл и сохранять все промежуточные данные для восстановления после сбоя.

## 2. Технологический стек
- Язык: Python 3.12+.
- Среда: `venv` + `uv`.
- GUI: современный desktop-интерфейс на базе Qt, предпочтительно PySide6.
- Работа с Excel: `openpyxl`.
- Экспорт и промежуточное хранение: CSV и JSON.
- Сборка в exe: PyInstaller.

## 3. Основной сценарий работы
1. Пользователь открывает файл регистрации участников в формате Excel.
2. Приложение загружает номер участника, ФИО и, если есть, время старта.
3. Судья запускает таймер кнопкой START или клавишей Space.
4. На финише судья вводит номер участника и ручное время секундомера.
5. Нажимается кнопка Finish! или Enter.
6. Данные сохраняются в памяти и на диск.
7. По кнопке Report формируется Excel-отчет и CSV-файл.

## 4. Интерфейс пользователя
- В верхней части окна расположен крупный таймер с точностью до 0,1 с.
- Справа от таймера находятся кнопки START, STOP, RESET.
- Ниже размещается поле ввода номера участника, доступен только цифровой ввод.
- Рядом размещается поле ручного времени судьи в формате `HHH:MM:ss.sss`.
- Справа от поля времени находится кнопка Finish!.
- Ниже отображается список уже записанных результатов.
- Поля номера и ручного времени в списке должны быть редактируемыми по двойному клику мышью.
- Между полями должна работать навигация по Tab.
- В нижней части окна должна быть статусная строка для отображения текущего состояния и ошибок.

## 5. Импорт файла регистрации
Файл регистрации должен быть Excel-документом. Из него необходимо загрузить:
- номер участника;
- ФИО;
- стартовое время, если оно указано.

Если в файле есть стартовое время, оно интерпретируется как `+MM:SS`. Если старт не указан, для всех участников используется общий старт. Структура столбцов должна быть настраиваемой или легко адаптируемой.

## 6. Логика расчета результата
Финальное время участника вычисляется либо по времени таймера приложения на момент финиша, либо по ручному времени секундомера судьи, с учетом времени старта. Если у участника задан персональный старт, используется он. Если персональный старт отсутствует, применяется общий старт. Штрафы в текущей версии могут быть сохранены как поле, но без активного расчета, если они не используются.

## 7. Сохранение промежуточного состояния
Приложение должно надежно сохранять промежуточные данные в файлы, чтобы при аварийном завершении можно было быстро восстановить состояние.

Должны сохраняться:
- загруженный файл регистрации;
- список уже записанных финишей;
- текущее состояние таймера;
- введенные, но не подтвержденные данные;
- сообщения об ошибках и служебные события.

Рекомендуется использовать отдельную папку данных приложения, например `data/` или `%APPDATA%/AppName/`.

## 8. Логирование ошибок и статусная строка
Приложение должно иметь централизованную систему логирования ошибок.

Требования:
- Все ошибки должны записываться в отдельный файл логов.
- Лог-файл должен содержать дату и время, уровень ошибки, источник, текст ошибки и, по возможности, стек вызова.
- Формат логов должен быть пригоден для последующего анализа и отладки.
- Критические ошибки должны отображаться в нижней статусной строке приложения.
- Некритические предупреждения также могут отображаться в статусной строке в кратком виде.
- Статусная строка должна показывать текущее состояние приложения, например: `Готово`, `Файл регистрации загружен`, `Ошибка: неверный формат времени`.
- При ошибке пользователь не должен терять уже введенные данные.
- После отображения ошибки приложение должно оставаться работоспособным, если это возможно.

## 9. Экспорт отчета
По нажатию на кнопку Report приложение должно сформировать:
- красиво оформленный Excel-файл с результатами;
- отдельный CSV-файл;
- при необходимости копию промежуточных данных для архивации.

В итоговом отчете должны быть колонки:
- Номер участника;
- ФИО;
- Место;
- Финальное время;
- Штрафные баллы/секунды.

Отчет должен быть отсортирован по месту и иметь читаемое форматирование таблицы.

## 10. Структура проекта
- `ui/` — окна, виджеты, статусная строка, обработчики событий.
- `core/` — модели данных, расчет времени, правила соревнований.
- `io/` — импорт Excel, экспорт Excel и CSV, сохранение состояния.
- `services/` — управление сессией, восстановление, логирование.
- `tests/` — unit-тесты и интеграционные тесты.

## 11. Роли ИИ-агентов
### Агент-архитектор
- Определяет структуру приложения.
- Делит проект на модули.
- Согласует интерфейсы между модулями.

### Агент GUI
- Реализует современный интерфейс.
- Настраивает табуляцию, редактирование, фокус и горячие клавиши.
- Добавляет статусную строку.

### Агент Excel/IO
- Реализует загрузку файла регистрации.
- Реализует экспорт отчетов.
- Настраивает сохранение данных в CSV и JSON.

### Агент логики времени
- Реализует таймер, старт, стоп, reset.
- Считает итоговое время.
- Обрабатывает персональные и общие старты.

### Агент надежности и логирования
- Реализует автосохранение.
- Восстанавливает состояние после сбоя.
- Записывает все ошибки в лог-файл.
- Передает краткое сообщение об ошибке в статусную строку.

### Агент упаковки
- Настраивает окружение `venv` + `uv`.
- Собирает exe через PyInstaller.
- Проверяет запуск на Windows 10/11.

## 12. Критерии приемки
- Приложение открывает Excel-файл регистрации и загружает данные участников.
- Таймер запускается кнопкой START и клавишей Space.
- Finish! сохраняет запись в память и на диск.
- Результаты отображаются в списке и могут редактироваться.
- Report создает Excel и CSV отчет.
- Промежуточные данные сохраняются для восстановления после сбоя.
- Все ошибки записываются в лог-файл.
- Ошибки и состояние отображаются в нижней строке статуса.
- Приложение запускается как exe на Windows 10/11.
- Версия приложения отображается в заголовке окна.
- Имя exe-файла содержит версию (например, `ChronoJudge_v1.0.0.exe`).
- Версия управляется через git-теги и файл версии в проекте.

## 14. Версионирование и Git
- Проект ведётся в Git-репозитории.
- Версия хранится в файле `version.txt` (или `pyproject.toml`) в формате SemVer: `MAJOR.MINOR.PATCH`.
- При сборке exe имя файла формируется как `ChronoJudge_v{version}.exe`.
- Заголовок главного окна: `ChronoJudge v{version}`.
- Релизы отмечаются git-тегами `v{version}`.
- История изменений ведётся в `CHANGELOG.md`.
